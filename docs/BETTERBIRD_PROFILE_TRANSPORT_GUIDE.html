Betterbird Profile Transport DIY Guide

Safe Fedora-to-antiX workflow for packing a whole Betterbird profile, transferring verified split archive parts, restoring to staging, and running the Maildir++ converter.

1. Goal

Use src/betterbird_profile_transport.py to move the whole Fedora Betterbird profile root ~/Betterbird-Email to antiX staging at /mail/import-staging/betterbird-maildir without changing message files. The transport script creates a streaming .tar.gz archive and splits it into verified part files. It does not zip the profile, it does not compact Betterbird folders, and it does not create one giant 60 GB archive file.

Default transport choices

  • Source scope: whole profile root contents.
  • Compression: Python standard-library gzip, level 6.
  • Part size: 1900 MiB.
  • Restore target: /mail/import-staging/betterbird-maildir.

Why 1900 MiB parts

A 59-60 GB profile may produce roughly 32 parts before compression. The 1900 MiB default stays below common 2 GB tool limits and well below the FAT32 4 GB file limit, while avoiding hundreds of tiny files.

2. Files Created by Pack

The export folder must remain together as one set. Transfer every file in it.

File Purpose
manifest.json Control file. Contains part names, sizes, hashes, whole archive hash, inventory metadata, source stats, timestamps, and restore defaults.
inventory.jsonl Per-entry inventory. Contains path, type, size, mode, mtime, and SHA256 for regular files. The script reads it automatically through the manifest.
betterbird-profile.tar.gz.part0001, part0002, ... Split archive stream. These are the transferable data files. The script verifies each part and the full reconstructed stream hash.

3. Manifest vs Inventory

Important: every command option named --manifest must point to manifest.json. Do not use inventory.jsonl as the control file.

manifest.json is the top-level control file. It tells the script where the part files are and how to verify inventory.jsonl. The inventory file must stay beside the manifest, but you do not pass it directly on the command line.

Correct verify-tree form 
python3 src/betterbird_profile_transport.py verify-tree \
  --manifest "$TRANSFER/manifest.json" \
  --dest /mail/import-staging/betterbird-maildir
Wrong file: $TRANSFER/inventory.jsonl. That file is not a manifest and will be rejected if used as the control file.

4. Prerequisites

  • Betterbird is fully closed on Fedora before packing.
  • Python 3 is available on Fedora and antiX.
  • This repository is available on both machines, or at least the two scripts under src/ are available on both machines.
  • The export location has enough free space for the compressed split archive parts.
  • The antiX staging disk has enough free space for the restored profile and later Maildir++ conversion output.
  • The transfer method preserves ordinary file bytes for manifest.json, inventory.jsonl, and all part files.
Check Python and repository on Fedora or antiX 
cd "$HOME/antiX_VM_Laptop"
python3 --version
test -f src/betterbird_profile_transport.py
test -f src/betterbird_maildirlite_to_maildirpp.py

5. Safety Rules

  • Do not compact Betterbird folders for this transport. The goal is an intact profile copy, not mail cleanup.
  • Do not extract or normalize the mail tree on Windows. Store the split part files on Windows if needed, but restore the profile on Linux.
  • Keep manifest.json, inventory.jsonl, and every betterbird-profile.tar.gz.partNNNN file together.
  • Use a fresh export directory outside ~/Betterbird-Email. The script refuses output inside the source tree.
  • Use an empty antiX destination. The script refuses a non-empty restore destination unless --allow-non-empty-dest is used after manual review.
  • Do not use --allow-active-profile, --allow-symlinks, or --allow-non-empty-dest for normal migration.

6. Fedora Pack Steps

Step 6.1 - Set variables

Use a fresh timestamped export folder outside the Betterbird profile.

Set Fedora paths 
export REPO="$HOME/antiX_VM_Laptop"
export SOURCE="$HOME/Betterbird-Email"
export EXPORT="$HOME/betterbird-profile-export-$(date +%Y%m%d-%H%M%S)"

Step 6.2 - Confirm Betterbird is closed

Close Betterbird normally from the UI first. Then check for running processes and lock markers.

Check process and lock markers 
pgrep -a betterbird || echo "No Betterbird process found"
find "$SOURCE" -maxdepth 1 \( -name ".parentlock" -o -name "parent.lock" -o -name "lock" \) -print
If any lock marker prints, do not pack yet. Reopen and close Betterbird cleanly, or restart Fedora and check again.

Step 6.3 - Check source and free space

Check profile size and disk space 
test -d "$SOURCE"
du -sh "$SOURCE"
df -h "$HOME"

Step 6.4 - Create the split archive export

This command creates manifest.json, inventory.jsonl, and split part files.

Pack the whole Betterbird profile 
cd "$REPO"
python3 src/betterbird_profile_transport.py pack \
  --source "$SOURCE" \
  --out "$EXPORT"
A successful run prints mode=pack, the manifest path, part count, archive bytes, and source file stats.

Step 6.5 - Confirm expected export files

List export folder 
ls -lh "$EXPORT"
test -f "$EXPORT/manifest.json"
test -f "$EXPORT/inventory.jsonl"
ls "$EXPORT"/betterbird-profile.tar.gz.part*

7. Transfer Checklist

Transfer the entire export folder to the antiX machine. You may use an external disk, shared folder, network copy, or another byte-preserving method.

If Windows is involved, use it only as storage for the export files. Do not extract the profile on Windows.
  • Transfer manifest.json.
  • Transfer inventory.jsonl.
  • Transfer every betterbird-profile.tar.gz.partNNNN file.
  • Keep the filenames unchanged.
  • Keep all files in one folder on antiX.

8. antiX Restore Steps

Step 8.1 - Set antiX paths

Set TRANSFER to the folder containing the copied export files.

Set antiX paths 
export REPO="$HOME/antiX_VM_Laptop"
export TRANSFER="/path/to/betterbird-profile-export"
export DEST="/mail/import-staging/betterbird-maildir"

Step 8.2 - Verify archive parts before extraction

This checks each part hash and the full reconstructed archive stream hash without making a huge combined archive.

Verify split archive 
cd "$REPO"
python3 src/betterbird_profile_transport.py verify-archive \
  --manifest "$TRANSFER/manifest.json"

Step 8.3 - Prepare an empty staging destination

The destination must be empty or absent. The script will create it if needed.

Inspect staging destination 
if [ -e "$DEST" ]; then
  find "$DEST" -mindepth 1 -maxdepth 1 -print -quit
else
  echo "Destination does not exist yet; the script can create it."
fi
If this command prints any file or folder under $DEST, do not run unpack until you have chosen a fresh empty destination or manually reviewed the old contents.

Step 8.4 - Unpack to antiX staging

This streams the split archive directly into the destination and rejects unsafe archive paths.

Unpack profile to staging 
cd "$REPO"
python3 src/betterbird_profile_transport.py unpack \
  --manifest "$TRANSFER/manifest.json" \
  --dest "$DEST"

Step 8.5 - Verify restored tree against inventory

This compares restored files against the inventory by path count, type, size, and SHA256 for regular files.

Verify restored profile tree 
cd "$REPO"
python3 src/betterbird_profile_transport.py verify-tree \
  --manifest "$TRANSFER/manifest.json" \
  --dest "$DEST"
Only continue to conversion after this command prints status=ok.

9. Maildir++ Conversion After Restore

After verify-tree passes, run the existing converter against the staged profile.

Step 9.1 - Dry run first

Converter dry run 
cd "$REPO"
python3 src/betterbird_maildirlite_to_maildirpp.py \
  --source "$DEST" \
  --target /mail/Mailstore/evolution-import \
  --dry-run

Step 9.2 - Review conversion logs

Review the log directory printed by the dry run. Important files include:

  • conversion.jsonl
  • folder-map.tsv
  • summary.tsv
  • duplicates.tsv
  • errors.tsv
  • skipped.tsv

Step 9.3 - Copy with resume support

Converter copy mode 
cd "$REPO"
python3 src/betterbird_maildirlite_to_maildirpp.py \
  --source "$DEST" \
  --target /mail/Mailstore/evolution-import \
  --copy \
  --resume

Step 9.4 - Verify copied Maildir++ output

Converter verify mode 
cd "$REPO"
python3 src/betterbird_maildirlite_to_maildirpp.py \
  --source "$DEST" \
  --target /mail/Mailstore/evolution-import \
  --verify \
  --verify-hash

10. Troubleshooting

Symptom Meaning Action
Active profile or lock marker error Betterbird may still be open or did not close cleanly. Close Betterbird, check pgrep -a betterbird, restart Fedora if needed, then pack again.
Missing archive part Not every partNNNN file reached antiX. Compare file counts and names with the Fedora export folder, then transfer the missing part.
SHA256 mismatch A part, inventory, or restored file changed during copy or storage. Re-transfer the affected files. If the mismatch remains, repack from Fedora after confirming the source is stable.
Non-empty destination refusal The staging directory already contains files. Choose a fresh destination or manually clear the staging directory outside the script after confirming it is safe.
inventory.jsonl used as the control file The wrong file was passed. Use --manifest "$TRANSFER/manifest.json". Keep inventory.jsonl beside it.
Symlink refusal The source tree contains symlinks and the default safe mode refuses them. Review whether those symlinks are expected. Do not use --allow-symlinks unless you understand their targets.
Interrupted pack, transfer, or unpack The export or restore may be incomplete. For pack, use a new export directory and run again. For transfer, rerun verify-archive. For unpack, use a fresh empty destination and run again.
