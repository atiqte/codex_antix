mbsync antiX Guide: INBOX Test and Production Provider-Live
===========================================================

Purpose
-------

This guide started as the first mbsync phase after Evolution Flatpak
validation. It installs and configures isync/mbsync for one standard IMAP INBOX
test pull into an isolated Maildir++ tree under /mail.

Current validated production state, as of 2026-06-27:

- The INBOX test path remains available at
  /mail/Mailstore/mbsync/provider-inbox-test.
- Production live mail is now under /mail/Mailstore/mbsync/provider-live.
- Normal production folders are receive-only.
- Sent is the only push-capable folder, through a narrow Sent-only channel.
- The 180-second auto-sync loop now syncs provider-live-group.

The first mbsync setup is intentionally conservative:

- Use antiX/Debian APT package isync instead of source-building.
- Pull only the provider INBOX at first.
- Store the first test under /mail/Mailstore/mbsync/provider-inbox-test.
- Keep sync state under /mail/AppData/isync/state/provider.
- Keep logs under /mail/Logs/mbsync.
- Use ~/.config/isyncrc with PassCmd reading ~/.config/isync/provider.pass.
- Do not push local changes to the provider.
- Do not propagate provider-side deletions to local archive mail.
- Do not expunge either side.
- Do not configure notmuch or Astroid yet.

Evolution remains the daily GUI client. notmuch/Astroid remains a later sidecar
search layer after Evolution and mbsync are proven on the real mail set.


Final Layout
------------

Target paths on antiX:

  /mail/Mailstore/evolution/local-maildir
    Converted Betterbird production archive. mbsync must not write here during
    the first test.

  /mail/Mailstore/mbsync/provider-inbox-test
    First isolated IMAP INBOX pull target.

  /mail/Mailstore/mbsync/provider-live
    Validated production live IMAP Maildir++ tree.

  /mail/AppData/isync/state/provider
    First INBOX test mbsync state files.

  /mail/AppData/isync/state/provider-live
    Production provider-live mbsync state files, including the reused Sent
    state file.

  /mail/Logs/mbsync
    First INBOX test mbsync run logs.

  /mail/Logs/mbsync-live
    Production provider-live mbsync logs.

  /mail/SearchIndex/notmuch
    Reserved for later notmuch index testing.

Local config paths:

  ~/.config/isyncrc
    mbsync config used with -c.

  ~/.config/isync/provider.pass
    Local password/app-password file. chmod 600. Do not share this file.


Safety Rules
------------

1. Keep the Betterbird converted archive and the mbsync test tree separate.
2. Use only INBOX until the first two manual syncs are clean.
3. Do not run Evolution against a Maildir while mbsync is actively writing it.
4. Do not paste passwords into chat or screenshots.
5. Review dry-run output before the first real pull.
6. Keep Remove None and Expunge None until deletion behavior is deliberately
   tested.
7. Keep normal production folders receive-only. Sent upload is the only
   approved push path.


Validated Production Provider-Live
----------------------------------

The production setup validated on 2026-06-27 uses these folders:

  INBOX
  Drafts
  Trash
  spam
  Sent
  Junk
  Archive

The current production config block is:

  # BEGIN CODEX MBSYNC PROVIDER LIVE
  # Production Maildir tree under /mail.
  # Receive-only for normal folders; Sent has a narrow PushNew-only upload path.
  MaildirStore provider-live-local
  Inbox /mail/Mailstore/mbsync/provider-live
  SubFolders Maildir++

  Channel provider-live
  Far :provider-remote:
  Near :provider-live-local:
  Patterns "INBOX" "Drafts" "Trash" "spam" "Junk" "Archive"
  Sync PullNew
  Create Near
  Remove None
  Expunge None
  CopyArrivalDate yes
  SyncState /mail/AppData/isync/state/provider-live/

  Channel provider-live-sent-upload
  Far :provider-remote:Sent
  Near :provider-live-local:Sent
  Sync PullNew PushNew
  Create None
  Remove None
  Expunge None
  CopyArrivalDate yes
  SyncState /mail/AppData/isync/state/provider-live/

  Group provider-live-group
  Channel provider-live
  Channel provider-live-sent-upload
  # END CODEX MBSYNC PROVIDER LIVE

Validated results:

- Sent upload test: remote INBOX.Sent increased from 4 to 5.
- Automatic Sent upload test: local Sent and remote INBOX.Sent both reached 6.
- Final audit: loop running, target provider-live-group, tmp count 0.

Helper Script
-------------

Run the helper from the repository root on the antiX VM:

  sh scripts/mbsync_provider_inbox_setup.sh inspect

Available commands:

  inspect
    Read-only system, disk, package, and current mbsync state check.

  install-packages
    Runs apt update and installs isync, ca-certificates, and libsasl2-modules.

  create-layout
    Creates the isolated Maildir++, state, log, and secret directories.

  write-config
    Prompts for IMAP host, username, and app password, then writes the pull-only
    config.

  list
    Lists the remote store and configured channel mailboxes.

  dry-run
    Runs verbose simulation mode. No mail or state files are modified.

  sync-once
    Runs one real INBOX pull and writes a timestamped log.

  status
    Shows counts, disk usage, sync-state files, sample files, and redacted
    config.

  redact-config
    Prints ~/.config/isyncrc with User and PassCmd redacted.

- mbsync may be missing before installation.

Batch 4 - Write Pull-Only Config
--------------------------------

Run locally on antiX. The password prompt is silent. Do not share the password
file or unredacted config.

  sh scripts/mbsync_provider_inbox_setup.sh write-config

The generated config uses this policy:

  Sync PullNew
  Create Near
  Remove None
  Expunge None
  CopyArrivalDate yes

Manual equivalent:

  set -eu

  printf 'IMAP host, example imap.example.com: '
  IFS= read -r IMAP_HOST
  printf 'IMAP username/email: '
  IFS= read -r IMAP_USER
  printf 'IMAP app password: '
  old_stty=$(stty -g 2>/dev/null || true)
  stty -echo 2>/dev/null || true
  IFS= read -r IMAP_PASS
  if [ -n "$old_stty" ]; then
    stty "$old_stty" 2>/dev/null || true
  else
    stty echo 2>/dev/null || true
  fi
  echo

  printf '%s\n' "$IMAP_PASS" > "$HOME/.config/isync/provider.pass"
  chmod 600 "$HOME/.config/isync/provider.pass"

  cat > "$HOME/.config/isyncrc" <<EOF
  FSync yes

  IMAPAccount provider
  Host $IMAP_HOST
  Port 993
  User $IMAP_USER
  PassCmd "cat ~/.config/isync/provider.pass"
  TLSType IMAPS
  SystemCertificates yes
  Timeout 60

  IMAPStore provider-remote
  Account provider

  MaildirStore provider-local
  Inbox /mail/Mailstore/mbsync/provider-inbox-test
  SubFolders Maildir++

  Channel provider-inbox
  Far :provider-remote:
  Near :provider-local:
  Sync PullNew
  Create Near
  Remove None
  Expunge None
  CopyArrivalDate yes
  SyncState /mail/AppData/isync/state/provider/
  EOF

  chmod 600 "$HOME/.config/isyncrc"

  sed -e 's/^User .*/User ***REDACTED***/' -e 's/^PassCmd .*/PassCmd ***REDACTED***/' "$HOME/.config/isyncrc"

Expected result:

- ~/.config/isyncrc exists and is chmod 600.
- ~/.config/isync/provider.pass exists and is chmod 600.
- Redacted config shows PullNew, Remove None, and Expunge None.

Batch 11 - Add One Second-Folder Test Channel
---------------------------------------------

Historical note: this was the conservative promotion path before the provider
was cleaned up to the exact seven desired folders. For the TAG Mustang mailbox,
this path was superseded by the validated provider-live setup documented above.
Keep this batch only as a fallback pattern for a future unknown provider.

After reviewing the remote folder list, choose exactly one small non-INBOX,
non-special folder. Set REMOTE_FOLDER to the exact remote name printed by
Batch 10.

This test maps that one remote folder into:

  /mail/Mailstore/mbsync/provider-folder-test

It does not use /mail/Mailstore/mbsync/provider-live.

  set -eu

  printf 'Exact remote folder name to test: '
  IFS= read -r REMOTE_FOLDER

  if [ -z "$REMOTE_FOLDER" ]; then
    echo "ERROR: remote folder name is required"
    exit 1
  fi

  case "$REMOTE_FOLDER" in
    INBOX|Trash|Junk|Spam|Sent|Drafts|Deleted*|*Trash*|*Junk*|*Spam*|*Sent*|*Draft*)
      echo "ERROR: choose a small low-risk non-special folder, not: $REMOTE_FOLDER"
      exit 1
      ;;
  esac

  TEST_ROOT=/mail/Mailstore/mbsync/provider-folder-test
  TEST_STATE=/mail/AppData/isync/state/provider-folder-test
  MARKER="# BEGIN CODEX MBSYNC PROVIDER SECOND FOLDER TEST"

  if grep -F "$MARKER" "$HOME/.config/isyncrc" >/dev/null 2>&1; then
    echo "ERROR: second-folder test block already exists in ~/.config/isyncrc"
    exit 1
  fi

  mkdir -p "$TEST_ROOT/cur" "$TEST_ROOT/new" "$TEST_ROOT/tmp" "$TEST_STATE"
  chmod 700 "$TEST_ROOT" "$TEST_ROOT/cur" "$TEST_ROOT/new" "$TEST_ROOT/tmp" "$TEST_STATE"

  BACKUP="$HOME/.config/isyncrc.before-second-folder.$(date +%Y%m%d-%H%M%S)"
  cp -p "$HOME/.config/isyncrc" "$BACKUP"

  REMOTE_ESCAPED=$(printf '%s' "$REMOTE_FOLDER" | sed 's/\\/\\\\/g; s/"/\\"/g')

  cat >> "$HOME/.config/isyncrc" <<EOF

# BEGIN CODEX MBSYNC PROVIDER SECOND FOLDER TEST
MaildirStore provider-folder-test-local
Inbox $TEST_ROOT
SubFolders Maildir++

Channel provider-folder-test
Far :provider-remote:"$REMOTE_ESCAPED"
Near :provider-folder-test-local:
Sync PullNew
Create Near
Remove None
Expunge None
CopyArrivalDate yes
SyncState $TEST_STATE/
# END CODEX MBSYNC PROVIDER SECOND FOLDER TEST
EOF

  chmod 600 "$HOME/.config/isyncrc"

  echo "Backed up previous config to: $BACKUP"
  echo
  echo "Second-folder test block:"
  sed -n '/BEGIN CODEX MBSYNC PROVIDER SECOND FOLDER TEST/,/END CODEX MBSYNC PROVIDER SECOND FOLDER TEST/p' "$HOME/.config/isyncrc"


Batch 12 - Pull the Second Folder Twice
---------------------------------------

Run only after Batch 11 creates the second-folder test channel.

  set -eu

  if pgrep -fa 'evolution|org.gnome.Evolution|bwrap|mbsync|isync' >/tmp/codex-mail-processes.txt 2>/dev/null; then
    cat /tmp/codex-mail-processes.txt
    echo "ERROR: close Evolution and stop mbsync before this test."
    exit 1
  fi

  for RUN in first second; do
    BEFORE=$(find /mail/Mailstore/mbsync/provider-folder-test/cur /mail/Mailstore/mbsync/provider-folder-test/new -type f | wc -l)
    LOG="/mail/Logs/mbsync/$(date +%Y%m%d-%H%M%S)-provider-folder-test-$RUN.log"

      STATUS=0
    else
      STATUS=$?
    fi
    AFTER=$(find /mail/Mailstore/mbsync/provider-folder-test/cur /mail/Mailstore/mbsync/provider-folder-test/new -type f | wc -l)

    echo "== $RUN run log =="
    cat "$LOG"
    echo "== $RUN run status =="
    echo "$STATUS"
    echo "before_count=$BEFORE"
    echo "after_count=$AFTER"
    echo "delta=$((AFTER - BEFORE))"
    echo -n "tmp: "
    find /mail/Mailstore/mbsync/provider-folder-test/tmp -type f | wc -l

    if [ "$STATUS" -ne 0 ]; then
      exit "$STATUS"
    fi
    sleep 2
  done


Historical Conservative Expansion Note
--------------------------------------

The following rule was used before production provider-live was validated. It
remains useful for a new provider, but it is no longer the current next action
for TAG Mustang.

For a new or unknown provider, do not add more folders until:

- Batch 5 dry-run is clean.
- Batch 6 real pull is clean.
- Evolution can read the test Maildir.
- Batch 8 second sync is clean.
- The logs show no unexpected push, delete, or expunge behavior.
- The working config/logs are snapshotted.
- Remote folders are listed read-only.
- One small second folder passes two real pulls without duplicate flood.

For a new provider, next expansion should still be conservative:

1. Pick one small low-risk folder.
2. Add one test channel or narrow mailbox selection.
3. Pull once with logging.
4. Pull a second time to confirm state handling.
5. Validate in Evolution only after mbsync exits.
6. Create /mail/Mailstore/mbsync/provider-live only after the previous folder is understood.

For the current TAG Mustang setup, provider-live already exists and is
validated. Normal folders remain receive-only, and Sent upload is handled only
by provider-live-sent-upload.


Troubleshooting
---------------

Problem: mbsync command not found.

Run:

  sh scripts/mbsync_provider_inbox_setup.sh install-packages


Problem: login fails.

Check:

- IMAP is enabled in the provider account.
- The username is the full email address if the provider requires it.
- The password is an app password if normal password login is blocked.
- The provider supports IMAPS on port 993.

Do not paste the password into chat.


Problem: dry-run lists many folders.

Stop. The first channel should be INBOX only. Review:

  sh scripts/mbsync_provider_inbox_setup.sh redact-config

For this first test there should be no Patterns line.


Problem: Evolution sees folder names but no messages.

In Evolution, remove the temporary account and recreate it as:

  Maildir-format mail directories

Do not choose:

  MH-format mail directories


Problem: local files disappear.

Stop using the channel and preserve the current files/logs. Check the config:

  grep -E '^(Sync|Create|Remove|Expunge) ' "$HOME/.config/isyncrc"

The first test must show:

  Sync PullNew
  Create Near
  Remove None
  Expunge None


Problem: sent messages do not appear on the IMAP server.

Check that Evolution saves sent copies to the production account:

  TAG-Mustang_mbsync-Live / Sent

Then verify:

  grep -RIn 'SentFolder=' "$HOME/.var/app/org.gnome.Evolution/config/evolution/sources"
  mbsync -c "$HOME/.config/isyncrc" --list provider-live-sent-upload
  mbsync-provider-live-control status

The expected channel mapping is:

  Sent <=> Sent

The loop/control scripts should target:

  CHANNEL="provider-live-group"


notmuch and Astroid Later
-------------------------

Do not install or configure notmuch/Astroid during the first mbsync phase.

After Evolution plus mbsync is stable, test notmuch as a sidecar index on a
copy or read-only workflow. The reserved path is:

  /mail/SearchIndex/notmuch

The goal is not to force Evolution to use notmuch. The goal is to keep
Evolution as the daily GUI and later evaluate notmuch/Astroid for very fast
search over very large local mail collections.
