notmuch + Astroid Search Layer for antiX Maildir++

Validated pilot guide for antiX Linux runit with zzzFM/IceWM, large Maildir++ storage on /mail, and Evolution Flatpak as the normal reply/send client.

Validated Result

notmuch backend: validated pilot index, 444 unique messages, 846 files.
Browser viewer: validated read-only GUI for search, exact Message-ID search, thread opening, and body rendering.
Astroid: installed and can list/search, but not primary because message bodies stayed blank on this VM.
Evolution handoff: raw Maildir file open is rejected because Evolution opened the wrong Berkeley mbox import workflow.

The reliable stack is: notmuch for fast search, localhost browser viewer for read-only search/view, and Evolution Flatpak for normal account-based reply/send.

Data safety overrides speed. Do not expand the notmuch index to the 59G archive until the count drift is reviewed: the archive later showed 48,564 cur files while the earlier verified restore ledger said 48,720.

Operating Rules

  • Never delete or rebuild Maildir data to fix notmuch. The notmuch database is disposable; the mail files are not.
  • Pause mbsync before full reindex work, then resume it after validation.
  • Keep maildir.synchronize_flags=false so notmuch tag changes do not rename Maildir files.
  • Back up tags with notmuch dump --format=batch-tag before any rebuild.
  • Use the browser viewer for notmuch search/view. Use Evolution from its configured Maildir accounts for reply, forward, edit, and send.
  • Do not use xdg-open on raw Maildir files for Evolution; it opened the wrong import wizard during validation.

Known Limitations

      
    
        
  • Astroid 0.16 on this antiX/IceWM/VMware setup displayed message lists but blank message bodies. The mail files and notmuch body output were valid, so the failure is treated as GUI rendering/client behavior, not index corruption.
    • 
        
  • Astroid needed symlink shims under the notmuch database path because it resolved mail paths relative to the database instead of the configured mail root.
    • 
        
  • Evolution Flatpak is not reliable as a raw Maildir file opener from notmuch. The validated wrong behavior was the Berkeley mbox import wizard.
    • 
        
  • Duplicate Message-ID values are expected in preserved archives. id: searches can match one logical message with multiple files.
    •
