# Go chi notmuch Browser Service for antiX

Updated: 2026-07-09

This is the rebuild guide for the read-only Go chi notmuch browser service on
antiX Linux runit with zzzFM/IceWM. It supersedes the Python pilot viewer as
the current service path and preserves the same safety posture:

- Search and view only.
- Evolution remains reply, forward, compose, and send.
- The HTTP service binds only to `127.0.0.1:8765`.
- Windows 11 access uses an SSH tunnel.
- Backend uses Go `net/http` plus the small `github.com/go-chi/chi/v5` router.
- UI uses modular embedded HTML templates, local HTMX, and compiled local Tailwind CSS.
- No React, Node/npm/Tailwind runtime on antiX, CDN, Gin, Flask, uv runtime, or tmux supervisor.
- notmuch is the search database; there is no custom mail database.
- The browser must not mutate Maildir data.

## Required Source Files

To rebuild from this repository, the antiX source tree needs these paths:

```text
go.mod
go.sum
cmd/notmuch-browser/
internal/notmuchbrowser/
scripts/notmuch_browser_control.sh
scripts/notmuch_browser_index_control.sh
```

If you do not want to clone the full repository on antiX, copy only those paths
into a temporary source directory, preserving the same relative layout. Then run
the build/install chunk from that directory.

The `internal/notmuchbrowser/` directory must include `templates/`, `static/`,
and `styles/`. The runtime serves only embedded local assets. Tailwind is a
build-time source workflow: `internal/notmuchbrowser/static/app.css` is the
compiled file used by antiX, and `internal/notmuchbrowser/styles/app.tailwind.css`
is the source file used only when regenerating CSS.

Optional development-host CSS regeneration, not required on antiX runtime:

```powershell
npx @tailwindcss/cli@4 -i internal/notmuchbrowser/styles/app.tailwind.css -o internal/notmuchbrowser/static/app.css --minify
go test ./...
```

## Chunk 1: antiX Safety Audit

Run before building or changing the service.

```sh
set -eu

CONFIG="$HOME/.config/notmuch/default/config"
MBSYNC_LOCK="/mail/AppData/isync/provider-live-loop/lock"

echo "== antiX notmuch browser safety audit =="
date -Is
echo

echo "== required commands =="
for c in go notmuch curl sh install; do
  if command -v "$c" >/dev/null 2>&1; then
    printf '%s=OK %s\n' "$c" "$(command -v "$c")"
  else
    printf '%s=MISSING\n' "$c"
  fi
done
echo

echo "== notmuch config safety =="
test -r "$CONFIG"
notmuch --config="$CONFIG" config get database.path
notmuch --config="$CONFIG" config get database.mail_root
notmuch --config="$CONFIG" config get maildir.synchronize_flags
notmuch --config="$CONFIG" config get index.decrypt
notmuch --config="$CONFIG" config get new.ignore
echo

echo "== notmuch counts =="
notmuch --config="$CONFIG" count '*'
notmuch --config="$CONFIG" count --output=files '*'
notmuch --config="$CONFIG" count tag:inbox
echo

echo "== locks and tmp files =="
test -d "$MBSYNC_LOCK" && echo "mbsync_lock=present" || echo "mbsync_lock=absent"
find /mail/Mailstore -type f -path '*/tmp/*' 2>/dev/null | wc -l | sed 's/^/maildir_tmp_files=/'
echo

echo "status=chunk1_safety_audit_complete"
```

Expected safety values:

```text
database.path=/mail/SearchIndex/notmuch/default
database.mail_root=/mail/Mailstore
maildir.synchronize_flags=false
index.decrypt=false
```

Stop if any value differs.

## Chunk 5: Repair Stale notmuch Paths

Use this if browser search shows errors like:

```text
Error opening /mail/Mailstore/mbsync/provider-live/new/...: No such file or directory
```

This is a stale notmuch database reference after Maildir renames. Do not
reinstall the app. Run a safe refresh.

```sh
set -eu

CONFIG="$HOME/.config/notmuch/default/config"
CONTROL="$HOME/.local/bin/notmuch-browser-control"
MBSYNC_LOCK="/mail/AppData/isync/provider-live-loop/lock"
STAMP="$(date +%Y%m%d-%H%M%S)"

echo "== stale index repair =="
date -Is
echo

echo "== before counts =="
notmuch --config="$CONFIG" count '*'
notmuch --config="$CONFIG" count --output=files '*'
notmuch --config="$CONFIG" count tag:inbox
echo

echo "== reproduce inbox metadata query =="
if notmuch --config="$CONFIG" show --format=json --entire-thread=false --body=false --offset=0 --limit=50 tag:inbox >/tmp/notmuch-before-"$STAMP".json 2>/tmp/notmuch-before-"$STAMP".err; then
  echo "before_query=OK"
else
  echo "before_query=FAILED"
  sed -n '1,80p' /tmp/notmuch-before-"$STAMP".err
fi
echo

echo "== refresh =="
if [ -d "$MBSYNC_LOCK" ]; then
  echo "status=blocked_mbsync_lock_present"
  exit 0
fi
"$CONTROL" refresh-index
echo

echo "== after query and browser =="
notmuch --config="$CONFIG" show --format=json --entire-thread=false --body=false --offset=0 --limit=50 tag:inbox >/tmp/notmuch-after-"$STAMP".json
wc -c /tmp/notmuch-after-"$STAMP".json
curl -fsS http://127.0.0.1:8765/healthz
echo
curl -fsS 'http://127.0.0.1:8765/search?q=tag%3Ainbox&offset=0&limit=10' >/tmp/notmuch-browser-after-repair.html
wc -c /tmp/notmuch-browser-after-repair.html
echo

echo "== tmp proof =="
find /mail/Mailstore -type f -path '*/tmp/*' 2>/dev/null | wc -l | sed 's/^/maildir_tmp_files=/'
echo

echo "status=chunk5_stale_index_repair_complete"
```

Validated 2026-07-09 repair result:

```text
before: 457 messages / 867 files
detected: 12 file renames
added: 102 new messages
after: 559 messages / 1,025 files
maildir_tmp_files=0
```

Counts will change as new mail arrives.

## Chunk 6: Install and Validate Automatic Index Refresh Loop

Run after installing `~/.local/bin/notmuch-browser-index-control`.

```sh
set -eu

INDEX="$HOME/.local/bin/notmuch-browser-index-control"

echo "== syntax and restart =="
sh -n "$INDEX"
"$INDEX" stop || true
"$INDEX" start

grep -F "# END NOTMUCH BROWSER INDEX REFRESH SERVICE" "$HOME/.icewm/startup" | wc -l | sed 's/^/end_marker_count=/'
```

## Runit Versus IceWM Startup

The validated current setup is IceWM user-session startup:

- `# BEGIN NOTMUCH BROWSER SERVICE`
- `# END NOTMUCH BROWSER SERVICE`
- `# BEGIN NOTMUCH BROWSER INDEX REFRESH SERVICE`
- `# END NOTMUCH BROWSER INDEX REFRESH SERVICE`

Use root-level runit only if boot-before-login is required. Do not use `tmux`
as the supervisor. It is acceptable only as a manual debugging console.

## Validation Checklist

On a recreated VM, do not consider the service complete until:

1. `go test ./...` passes.
2. `internal/notmuchbrowser/static/app.css` exists and is served from `/static/app.css`.
3. Browser service reports `server=running`.
4. Index loop reports `loop=running`.
5. `/healthz` returns `ok:true`.
6. `tag:inbox` search renders.
7. A single message opens.
8. HTML mail renders in the sandboxed iframe.
9. Attachment names display.
10. Duplicate selector displays for duplicate Message-ID messages.
11. Windows SSH tunnel works.
12. Maildir `tmp` count remains 0 after search/view/refresh.
13. IceWM startup has exactly one begin/end marker for both browser and index loop.
