Purpose

This guide implements the first mbsync phase after Evolution Flatpak validation. It installs and configures isync/mbsync for one standard IMAP INBOX test pull into an isolated Maildir++ tree under /mail.

First target

/mail/Mailstore/mbsync/provider-inbox-test

Policy

Sync PullNew, Create Near, Remove None, and Expunge None.

Do not install notmuch or Astroid in this phase. They remain later sidecar search tests after Evolution and mbsync are stable.

Safety Rules

  • Keep the Betterbird converted archive and mbsync test tree separate.
  • Use only INBOX until the first two manual syncs are clean.
  • Do not run Evolution against a Maildir while mbsync is actively writing it.
  • Do not paste passwords into chat or screenshots.
  • Review dry-run output before the first real pull.
  • Keep Remove None and Expunge None until deletion behavior is deliberately tested.

Helper Script

Run commands from the repository root on the antiX VM.

Show helper usage
sh scripts/mbsync_provider_inbox_setup.sh --help

The helper supports inspect, install-packages, create-layout, write-config, list, dry-run, sync-once, status, and redact-config.

Batch 1 - Discovery Only

Inspect current antiX state
sh scripts/mbsync_provider_inbox_setup.sh inspect

Expected result: /mail is mounted, APT shows isync as available, and mbsync may be missing before installation.

Batch 2 - Install mbsync

Install isync/mbsync
sh scripts/mbsync_provider_inbox_setup.sh install-packages

Expected result: mbsync --version prints version information. Do not install notmuch or Astroid in this phase.

Batch 3 - Create Isolated Layout

Create /mail layout
sh scripts/mbsync_provider_inbox_setup.sh create-layout

Expected result: the test Maildir has cur, new, and tmp; state and logs live under /mail.

Batch 4 - Write Pull-Only Config

The helper prompts for IMAP host, username, and app password locally on antiX. The password prompt is silent. Do not share the password file or unredacted config.

Create first mbsync config
sh scripts/mbsync_provider_inbox_setup.sh write-config
Show redacted config
sh scripts/mbsync_provider_inbox_setup.sh redact-config

Batch 5 - List and Dry-Run

List remote/channel mailboxes
sh scripts/mbsync_provider_inbox_setup.sh list
Dry-run the INBOX pull
sh scripts/mbsync_provider_inbox_setup.sh dry-run

Expected result: authentication succeeds, the channel mailbox is INBOX only, and dry-run shows pulls rather than pushes or expunges.

Batch 6 - First Real Pull

Run this only after the dry-run output is clean.
Pull INBOX once
sh scripts/mbsync_provider_inbox_setup.sh sync-once
Show status after sync
sh scripts/mbsync_provider_inbox_setup.sh status

Expected result: messages appear under cur or new, a timestamped log is saved, and the production Betterbird/Evolution archive is untouched.

Evolution Read Test

After mbsync exits, launch Evolution and add a temporary local Maildir account.

Receiving typeMaildir-format mail directories
Path/mail/Mailstore/mbsync/provider-inbox-test

Validate message reading, HTML rendering, attachments, dates, and Evolution search. Then close Evolution before the next mbsync run.

Stop Evolution before next sync
flatpak kill org.gnome.Evolution 2>/dev/null || true
pgrep -fa 'evolution|org.gnome.Evolution|bwrap' || true

Next Steps

Run one more manual sync after Evolution is closed:

Second manual sync
sh scripts/mbsync_provider_inbox_setup.sh sync-once

Do not add more folders until the dry-run, first pull, Evolution read test, and second sync are all clean.

Troubleshooting

ProblemAction
mbsync command not found.Run sh scripts/mbsync_provider_inbox_setup.sh install-packages.
Login fails.Confirm IMAP is enabled, username format is correct, an app password is used if required, and port 993 is supported.
Dry-run lists many folders.Stop. Review sh scripts/mbsync_provider_inbox_setup.sh redact-config; the first test should target INBOX only.
Evolution sees folders but no messages.Recreate the account as Maildir-format mail directories, not MH-format mail directories.
Local files disappear.Stop using the channel and verify the config still says Sync PullNew, Remove None, and Expunge None.
