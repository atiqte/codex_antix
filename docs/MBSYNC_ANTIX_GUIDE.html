Purpose

This guide started as the first mbsync phase after Evolution Flatpak validation. It installs and configures isync/mbsync for one standard IMAP INBOX test pull into an isolated Maildir++ tree under /mail.

First target

/mail/Mailstore/mbsync/provider-inbox-test

Policy

Sync PullNew, Create Near, Remove None, and Expunge None.

Current production state: /mail/Mailstore/mbsync/provider-live is now validated. Normal folders are receive-only, Sent upload is handled by a narrow Sent-only channel, and the 180-second loop syncs provider-live-group.

Safety Rules

  • Keep the Betterbird converted archive and mbsync test tree separate.
  • Use only INBOX until the first two manual syncs are clean.
  • Do not run Evolution against a Maildir while mbsync is actively writing it.
  • Do not paste passwords into chat or screenshots.
  • Review dry-run output before the first real pull.
  • Keep Remove None and Expunge None until deletion behavior is deliberately tested.
  • Keep normal production folders receive-only. Sent upload is the only approved push path.

Validated Production Provider-Live

The production setup validated on 2026-06-27 uses INBOX, Drafts, Trash, spam, Sent, Junk, and Archive. Normal folders stay receive-only; Sent is uploaded through one narrow Sent-only channel.

Current production mbsync block
# BEGIN CODEX MBSYNC PROVIDER LIVE
# Production Maildir tree under /mail.
# Receive-only for normal folders; Sent has a narrow PushNew-only upload path.
MaildirStore provider-live-local
Inbox /mail/Mailstore/mbsync/provider-live
SubFolders Maildir++

Channel provider-live
Far :provider-remote:
Near :provider-live-local:
Patterns "INBOX" "Drafts" "Trash" "spam" "Junk" "Archive"
Sync PullNew
Create Near
Remove None
Expunge None
CopyArrivalDate yes
SyncState /mail/AppData/isync/state/provider-live/

Channel provider-live-sent-upload
Far :provider-remote:Sent
Near :provider-live-local:Sent
Sync PullNew PushNew
Create None
Remove None
Expunge None
CopyArrivalDate yes
SyncState /mail/AppData/isync/state/provider-live/

Group provider-live-group
Channel provider-live
Channel provider-live-sent-upload
# END CODEX MBSYNC PROVIDER LIVE

Pull second-folder test twice
set -eu

if pgrep -fa 'evolution|org.gnome.Evolution|bwrap|mbsync|isync' >/tmp/codex-mail-processes.txt 2>/dev/null; then
  cat /tmp/codex-mail-processes.txt

for RUN in first second; do
  BEFORE=$(find /mail/Mailstore/mbsync/provider-folder-test/cur /mail/Mailstore/mbsync/provider-folder-test/new -type f | wc -l)
  LOG="/mail/Logs/mbsync/$(date +%Y%m%d-%H%M%S)-provider-folder-test-$RUN.log"
  if mbsync -c "$HOME/.config/isyncrc" -V provider-folder-test > "$LOG" 2>&1; then
    STATUS=0
  else
    STATUS=$?
  fi
  AFTER=$(find /mail/Mailstore/mbsync/provider-folder-test/cur /mail/Mailstore/mbsync/provider-folder-test/new -type f | wc -l)

  echo "== $RUN run log =="
  cat "$LOG"
  echo "== $RUN run status =="
  echo "$STATUS"

  echo "after_count=$AFTER"
  echo "delta=$((AFTER - BEFORE))"
  echo -n "tmp: "
  find /mail/Mailstore/mbsync/provider-folder-test/tmp -type f | wc -l

  if [ "$STATUS" -ne 0 ]; then
    exit "$STATUS"
  fi

Troubleshooting

ProblemAction
mbsync command not found.Run sh scripts/mbsync_provider_inbox_setup.sh install-packages.
Login fails.Confirm IMAP is enabled, username format is correct, an app password is used if required, and port 993 is supported.
Dry-run lists many folders.Stop. Review sh scripts/mbsync_provider_inbox_setup.sh redact-config; the first test should target INBOX only.
Evolution sees folders but no messages.Recreate the account as Maildir-format mail directories, not MH-format mail directories.
Local files disappear.Stop using the channel and verify the config still says Sync PullNew, Remove None, and Expunge None.
Sent messages do not appear on the IMAP server.Verify Evolution saves sent copies to TAG-Mustang_mbsync-Live / Sent, mbsync --list provider-live-sent-upload prints Sent <=> Sent, and loop/control scripts show CHANNEL="provider-live-group".
