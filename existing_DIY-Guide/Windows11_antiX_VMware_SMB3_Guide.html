0. Scope, confirmed values, and design rules

This document describes the complete end-to-end procedure for configuring a robust SMB3 transfer channel between a Windows 11 25H2 host and an antiX Linux Runit zzzFM-IceWM guest running inside VMware Workstation Pro 26H1.

The intended use is frequent two-way file transfer for Betterbird attachments, PDFs, Excel files, images, exported documents, scanned files, and mixed small/medium/large files. The SMB share is not designed to hold the active Betterbird profile, active Maildir store, Logseq database, or any continuously indexed database. Keep those on the antiX VM local virtual disk. Use this SMB share only as an exchange/staging area.

Confirmed values from the completed setup:

Windows computer name: DESKTOP-JPMLALG
Windows VMnet1 host-only IP: 192.168.4.1/24
Windows SMB share name: VMXFER
Windows SMB share path: F:\VM-SMB-Exchange
Windows SMB local user: smbvm
antiX mount point: /mnt/win-vmxfer
antiX user and group: uid=1000(atiq), gid=1000(atiq)
VMware topology: NAT on Adapter 1, host-only VMnet1 on Adapter 2

If your VMnet1 IP, Windows computer name, username, or mount point is different, adjust the commands consistently. In this confirmed setup, use `192.168.4.1`, not `192.168.56.1`.

The professional design is:

Adapter 1: NAT / VMnet8
  Purpose: Internet access for antiX.
  Default route: allowed.

Adapter 2: Host-only / VMnet1
  Purpose: private SMB3 transfer path between Windows host and antiX guest.
  Default route: not needed.

Windows host:
  SMB3 server.
  Share only F:\VM-SMB-Exchange as VMXFER.
  Firewall allows TCP 445 only on VMware Network Adapter VMnet1.

antiX guest:
  SMB/CIFS client.
  noauto fstab entry.
  On-demand mount/unmount scripts.
  zzzFM bookmark.
  IceWM menu entries.
  YAD live tray status indicator.

Do not use bridged networking for the SMB transfer path unless you intentionally want the share exposed on the physical LAN. Host-only VMnet1 is the correct private design.

1. VMware Workstation Pro 26H1 network topology

Power off the antiX VM before changing virtual network adapters.

Open VMware Workstation Pro and configure the antiX VM as follows.

Network Adapter 1:

Network Adapter 1:
  NAT: used to share the host's IP address
  Prefer VMnet8
  Connect at power on: enabled

Network Adapter 2:

Network Adapter 2:
  Host-only: private network shared with the host
  Prefer VMnet1
  Connect at power on: enabled

Critical rule: Adapter 1 is for Internet. Adapter 2 is for SMB3 transfer. Do not use the Internet/NAT adapter as your SMB path if the dedicated host-only adapter is working.

After booting Windows, confirm that VMnet1 exists and has an IPv4 address. Run PowerShell as Administrator:

Get-NetAdapter | Where-Object {$_.Name -like "*VMnet*"} |
  Format-Table Name,InterfaceDescription,Status,ifIndex,MacAddress

Get-NetIPAddress -AddressFamily IPv4 |
  Where-Object {$_.InterfaceAlias -like "*VMnet1*"} |
  Format-Table InterfaceAlias,IPAddress,PrefixLength

Expected for this specific machine:

InterfaceAlias                  IPAddress      PrefixLength
--------------                  ---------      ------------
VMware Network Adapter VMnet1    192.168.4.1    24

The antiX guest should later receive an address like `192.168.4.x` on its host-only interface.

2. Windows firewall rule for host-only SMB3

Windows firewall must allow SMB only on VMnet1, not on Wi-Fi/Ethernet/bridged public networks.

Run PowerShell as Administrator:

$RuleName = "VMware Host-Only SMB3 to antiX VM only"
Get-NetFirewallRule -DisplayName $RuleName -ErrorAction SilentlyContinue | Remove-NetFirewallRule

New-NetFirewallRule `
  -DisplayName "VMware Host-Only SMB3 to antiX VM only" `
  -Direction Inbound `
  -Action Allow `
  -Protocol TCP `
  -LocalPort 445 `
  -InterfaceAlias "VMware Network Adapter VMnet1" `
  -RemoteAddress 192.168.4.0/24 `
  -Profile Any

Verify the rule:

Get-NetFirewallRule -DisplayName "VMware Host-Only SMB3 to antiX VM only" |
  Format-List DisplayName,Enabled,Direction,Action,Profile

Get-NetFirewallRule -DisplayName "VMware Host-Only SMB3 to antiX VM only" |
  Get-NetFirewallPortFilter |
  Format-List Protocol,LocalPort

Get-NetFirewallRule -DisplayName "VMware Host-Only SMB3 to antiX VM only" |
  Get-NetFirewallAddressFilter |
  Format-List RemoteAddress

Get-NetFirewallRule -DisplayName "VMware Host-Only SMB3 to antiX VM only" |
  Get-NetFirewallInterfaceFilter |
  Format-List InterfaceAlias

Correct characteristics:

Enabled: True
Direction: Inbound
Action: Allow
Profile: Any
Protocol: TCP
LocalPort: 445
RemoteAddress: 192.168.4.0/24
InterfaceAlias: VMware Network Adapter VMnet1

Using `Profile Any` is acceptable here because the rule is constrained by interface alias and remote subnet. This is important because Windows may not show a normal network profile for VMnet1.

3. Windows SMB server baseline

Confirm the Windows SMB server service is running:

Get-Service LanmanServer

Confirm that Windows is listening on TCP port 445:

Get-NetTCPConnection -LocalPort 445 -State Listen

Configure the SMB protocol baseline:

Set-SmbServerConfiguration `
  -EnableSMB1Protocol $false `
  -EnableSMB2Protocol $true `
  -Confirm:$false

Get-SmbServerConfiguration |
  Select-Object EnableSMB1Protocol,EnableSMB2Protocol,EncryptData,RejectUnencryptedAccess,RequireSecuritySignature,EnableSecuritySignature

Expected baseline:

EnableSMB1Protocol       : False
EnableSMB2Protocol       : True
EncryptData              : False
RejectUnencryptedAccess  : True
RequireSecuritySignature : True
EnableSecuritySignature  : False

`EnableSMB2Protocol=True` is correct. Windows uses this setting for SMB2 and SMB3. Do not disable it.

SMB signing and SMB encryption are not the same thing. Signing protects message integrity. Encryption protects confidentiality over the network. Because this transfer path is a private VMware host-only link, the share is configured with `EncryptData $false` for performance. If you ever expose the share over bridged/LAN networking, reassess this choice.

4. Create the dedicated Windows SMB user

Use a dedicated Windows local user for the VM. Do not use your main Windows administrator account for routine SMB transfers.

PowerShell `else` blocks are easy to break if pasted line-by-line. The robust method below avoids `else` entirely. Run PowerShell as Administrator and paste the whole block.

Important: Windows local-user description has a 48-character limit. Use the short description below.

$User = "smbvm"
$FullName = "VM SMB Transfer User"
$Desc = "antiX VM SMB file transfer"
$Pass = Read-Host "Enter a strong password for smbvm" -AsSecureString

$ExistingUser = Get-LocalUser -Name $User -ErrorAction SilentlyContinue

if ($null -eq $ExistingUser) {
    New-LocalUser `
      -Name $User `
      -Password $Pass `
      -FullName $FullName `
      -Description $Desc `
      -AccountNeverExpires `
      -PasswordNeverExpires
}

$CheckUser = Get-LocalUser -Name $User -ErrorAction Stop

Set-LocalUser `
  -Name $User `
  -Password $Pass `
  -FullName $FullName `
  -Description $Desc `
  -PasswordNeverExpires $true

Enable-LocalUser -Name $User

net user smbvm /passwordreq:yes
net user smbvm /active:yes
net user smbvm /expires:never

Get-LocalUser -Name $User | Format-List Name,Enabled,FullName,Description,PasswordRequired,PasswordLastSet
net user smbvm

Correct checkpoint:

Name             : smbvm
Enabled          : True
FullName         : VM SMB Transfer User
Description      : antiX VM SMB file transfer
PasswordRequired : True

Account active               Yes
Account expires              Never
Password required            Yes
Password expires             Never

Write down the password safely. It will be stored on antiX in `/root/.smbcredentials/vmxfer.cred` with root-only permission.

6. Use F: drive for the SMB exchange folder

The completed setup uses `F:\VM-SMB-Exchange`. This keeps the exchange folder away from the Windows system partition.

Confirm that `F:` is accessible:

Test-Path F:\

Expected:

True

Check BitLocker state:

Get-BitLockerVolume -MountPoint "F:" |
  Format-List MountPoint,VolumeStatus,ProtectionStatus,LockStatus,EncryptionPercentage

Confirmed result:

MountPoint           : F:
VolumeStatus         : FullyEncrypted
ProtectionStatus     : Off
LockStatus           : Unlocked
EncryptionPercentage : 100

Interpretation: the drive is fully encrypted and currently unlocked, so it is usable for SMB. `ProtectionStatus: Off` means BitLocker protection is suspended/off for that volume; it does not block SMB operation. Later, you may re-enable BitLocker protection if desired. For SMB setup, the important line is `LockStatus: Unlocked`.

Operational rule: after reboot, Windows must have `F:` unlocked before antiX can access the SMB share.

8. Apply NTFS permissions

NTFS permissions are the real filesystem permissions. SMB share permissions sit on top of NTFS permissions. Both must allow access.

Run PowerShell as Administrator:

$User = "smbvm"
$Root = "F:\VM-SMB-Exchange"
$Account = "$env:COMPUTERNAME\$User"

icacls $Root /inheritance:r
icacls $Root /grant:r "${Account}:(OI)(CI)M" "*S-1-5-32-544:(OI)(CI)F" "*S-1-5-18:(OI)(CI)F"
icacls $Root /remove:g "Users" "Authenticated Users" "Everyone"
icacls $Root

The `${Account}` syntax is intentional. Without braces, PowerShell can misread the colon after the variable.

Correct result:

F:\VM-SMB-Exchange NT AUTHORITY\SYSTEM:(OI)(CI)(F)
                   BUILTIN\Administrators:(OI)(CI)(F)
                   DESKTOP-JPMLALG\smbvm:(OI)(CI)(M)

Meaning:

SYSTEM: full control
Administrators: full control
smbvm: modify, inherited to files/folders

9. Create the Windows SMB share

Create the share named `VMXFER` pointing to `F:\VM-SMB-Exchange`.

Run PowerShell as Administrator:

$ShareName = "VMXFER"
$Root = "F:\VM-SMB-Exchange"
$User = "smbvm"
$Account = "$env:COMPUTERNAME\$User"

if (Get-SmbShare -Name $ShareName -ErrorAction SilentlyContinue) {
    Remove-SmbShare -Name $ShareName -Force
}

New-SmbShare `
  -Name $ShareName `
  -Path $Root `
  -ChangeAccess $Account `
  -FullAccess "BUILTIN\Administrators" `
  -CachingMode None `
  -FolderEnumerationMode AccessBased `
  -EncryptData $false

Get-SmbShare -Name VMXFER
Get-SmbShareAccess -Name VMXFER

Correct result:

Name   ScopeName Path
----   --------- ----
VMXFER *         F:\VM-SMB-Exchange

Name   AccountName              AccessRight
----   -----------              -----------
VMXFER BUILTIN\Administrators   Full
VMXFER DESKTOP-JPMLALG\smbvm    Change

15. Add the antiX fstab entry with noauto

Use a manual/on-demand mount. Do not auto-mount this SMB share at boot.

Reason: antiX Runit does not provide the same systemd-style network-online automount behavior. SMB mount during boot can race with VMware adapters, DHCP, Windows SMB service, firewall readiness, or BitLocker unlock state. `noauto,_netdev,nofail` keeps boot clean and lets the user mount only when needed.

Edit `/etc/fstab`:

sudo fresh /etc/fstab

Fallback:

sudo nano /etc/fstab

Add this one-line entry:

//192.168.4.1/VMXFER /mnt/win-vmxfer cifs credentials=/root/.smbcredentials/vmxfer.cred,vers=3.1.1,uid=1000,gid=1000,file_mode=0660,dir_mode=0770,iocharset=utf8,noperm,serverino,actimeo=5,cache=strict,mfsymlinks,nosharesock,_netdev,nofail,noauto 0 0

Meaning of key options:

credentials=...       Use root-only credential file.
vers=3.1.1            Prefer SMB 3.1.1.
uid=1000,gid=1000     Show files as owned by antiX user atiq.
file_mode=0660        Files writable by owner/group.
dir_mode=0770         Directories accessible by owner/group.
iocharset=utf8        Correct Unicode filename handling.
noperm                Let Windows SMB/NTFS permissions decide access.
serverino             Use server-provided inode numbers.
actimeo=5             Short attribute cache, good balance for two-way transfer.
cache=strict          Safer cache behavior.
mfsymlinks            Map symlinks in a Windows-compatible way.
nosharesock           Avoid shared socket reuse issues.
_netdev,nofail        Network filesystem, do not block boot.
noauto                Do not mount automatically at boot.

Verify from Windows:

Get-Content F:\VM-SMB-Exchange\02_From_VM_To_Windows\antix-mounted-test.txt

Unmount:

sync
sudo umount /mnt/win-vmxfer

After unmount, `/mnt/win-vmxfer` should look like an empty local directory. That is normal.

Avoid running `sudo mount /mnt/win-vmxfer` twice. Linux can stack mounts on the same mount point. If you accidentally mount twice, one `umount` removes only one layer. The robust unmount script later handles this.

17. Create the robust mount script

This script uses TCP port 445 reachability with `nc`, not ping. Ping can fail even when SMB works because Windows may block ICMP.

Create:

sudo fresh /usr/local/bin/mount-vmxfer

Fallback:

sudo nano /usr/local/bin/mount-vmxfer

Paste:

#!/bin/sh

HOST_IP="192.168.4.1"
MNT="/mnt/win-vmxfer"
CREDS="/root/.smbcredentials/vmxfer.cred"

mkdir -p "$MNT"

if mountpoint -q "$MNT"; then
    echo "$MNT is already mounted."
    exit 0
fi

if [ ! -f "$CREDS" ]; then
    echo "ERROR: SMB credentials file is missing: $CREDS"
    exit 1
fi

CREDS_PERM="$(stat -c '%a' "$CREDS" 2>/dev/null)"
if [ "$CREDS_PERM" != "600" ]; then
    echo "WARNING: $CREDS permission is $CREDS_PERM, recommended is 600."
    echo "Fix with: sudo chmod 600 $CREDS"
fi

if ! awk '$2 == "/mnt/win-vmxfer" {found=1} END {exit !found}' /etc/fstab; then
    echo "ERROR: $MNT is not defined in /etc/fstab."
    exit 1
fi

nc -z -w 2 "$HOST_IP" 445 >/dev/null 2>&1 || {
    echo "ERROR: SMB TCP/445 on $HOST_IP is not reachable."
    echo "Check Windows, F: drive unlock state, VMware VMnet1, and firewall."
    exit 1
}

if mount "$MNT"; then
    echo "Mounted $MNT"
else
    echo "ERROR: Failed to mount $MNT"
    echo "Diagnostic commands:"
    echo "  sudo mount -v $MNT"
    echo "  smbclient -L //$HOST_IP -m SMB3 -U 'DESKTOP-JPMLALG\\smbvm'"
    exit 1
fi

Make it executable:

sudo chmod +x /usr/local/bin/mount-vmxfer

18. Create the robust unmount script

This version handles accidental stacked/double mounts by looping until the mount point is actually unmounted.

Create:

sudo fresh /usr/local/bin/umount-vmxfer

Fallback:

sudo nano /usr/local/bin/umount-vmxfer

Paste:

#!/bin/sh

MNT="/mnt/win-vmxfer"

if ! mountpoint -q "$MNT"; then
    echo "$MNT is not mounted."
    exit 0
fi

sync

COUNT=0
while mountpoint -q "$MNT"; do
    COUNT=$((COUNT + 1))

    if [ "$COUNT" -gt 5 ]; then
        echo "ERROR: $MNT is still mounted after 5 unmount attempts."
        echo "Most likely cause: zzzFM, terminal, Betterbird file picker, or another process is using it."
        echo
        echo "Check with:"
        echo "  fuser -vm $MNT"
        echo
        echo "Then close the process or leave the directory and retry:"
        echo "  cd ~"
        echo "  sudo umount $MNT"
        exit 1
    fi

    if ! umount "$MNT"; then
        echo "ERROR: Failed to unmount $MNT"
        echo "Most likely cause: a process is using the mount."
        echo
        echo "Check with:"
        echo "  fuser -vm $MNT"
        exit 1
    fi
done

echo "Unmounted $MNT"
exit 0

Make it executable:

sudo chmod +x /usr/local/bin/umount-vmxfer

Test:

sudo /usr/local/bin/mount-vmxfer
findmnt /mnt/win-vmxfer
sudo /usr/local/bin/umount-vmxfer
findmnt /mnt/win-vmxfer || echo "Cleanly unmounted"

21. YAD live tray indicator without changing taskbar size

This creates a live tray icon in IceWM showing the present state of `/mnt/win-vmxfer`.

Design:

Green check icon = mounted
Red cross icon = unmounted

24. Betterbird usage rules

For Betterbird, use this SMB share for attachments and file exchange only.

Recommended pattern:

Incoming files from Windows:
  F:\VM-SMB-Exchange\01_From_Windows_To_VM
  visible in antiX as /mnt/win-vmxfer/01_From_Windows_To_VM

Outgoing files from antiX:
  /mnt/win-vmxfer/02_From_VM_To_Windows
  visible in Windows as F:\VM-SMB-Exchange\02_From_VM_To_Windows

Betterbird attachments staging:
  /mnt/win-vmxfer/03_Betterbird_Attachments

Do not put these on SMB:

Betterbird profile
Betterbird Maildir store
Thunderbird/Betterbird global-messages-db.sqlite
Logseq DB
millions of .eml files
active search indexes
SQLite databases

Reason: SMB is excellent for file exchange but not ideal for active database/index/maildir workloads inside a VM. For millions of `.eml` messages and fast searching, keep the store local on the antiX virtual disk and use SMB only to import/export files.

27. Troubleshooting

Problem: `ping 192.168.4.1` fails, but `nc -vz 192.168.4.1 445` succeeds.
Meaning: not a problem. Windows is probably blocking ICMP. SMB works over TCP 445.

Problem: `SMB1 disabled -- no workgroup available` appears.
Meaning: normal. You are using direct SMB3 by IP. Workgroup browsing is unnecessary.

Problem: `smbclient` authentication fails.
Check:

Windows computer name: DESKTOP-JPMLALG
Username: smbvm
Command format: smbclient //192.168.4.1/VMXFER -m SMB3 -U 'DESKTOP-JPMLALG\smbvm'
Password: exact smbvm password
Windows account active: net user smbvm

Problem: access denied after login.
Check both permission layers:

Get-SmbShareAccess -Name VMXFER
icacls F:\VM-SMB-Exchange

Problem: fstab mount fails but smbclient works.
Check credential file:

sudo sh -c 'sed -E "s/^password=.*/password=<hidden>/" /root/.smbcredentials/vmxfer.cred'
sudo ls -l /root/.smbcredentials/vmxfer.cred
sudo mount -v /mnt/win-vmxfer

Problem: findmnt still shows the mount after one unmount.
Likely cause: you mounted the same mount point twice. Use the robust script:

sudo /usr/local/bin/umount-vmxfer

Problem: unmount says target is busy.
Check:

fuser -vm /mnt/win-vmxfer
cd ~
sudo /usr/local/bin/umount-vmxfer

Close zzzFM, Betterbird file picker, or terminals currently inside `/mnt/win-vmxfer`.

Problem: tray icon does not appear.
Check:

command -v yad
pgrep -af vmxfer-tray
pgrep -af yad

Enable tray display without changing taskbar size:

mkdir -p ~/.icewm
touch ~/.icewm/prefoverride
grep -q '^TaskBarShowTray=' ~/.icewm/prefoverride || echo 'TaskBarShowTray=1' >> ~/.icewm/prefoverride
grep -q '^TaskBarEnableSystemTray=' ~/.icewm/prefoverride || echo 'TaskBarEnableSystemTray=1' >> ~/.icewm/prefoverride

Problem: the icon is too small.
Do not rely on tiny text in the SVG. Use large check/cross icons. This guide intentionally avoids changing the default taskbar size.

Problem: Windows F: drive is locked.
Unlock F: in Windows first. Then remount from antiX.

Problem: VMnet1 IP changes.
Re-check Windows VMnet1 IP and update all locations if needed:

Get-NetIPAddress -AddressFamily IPv4 |
  Where-Object {$_.InterfaceAlias -like "*VMnet1*"} |
  Format-Table InterfaceAlias,IPAddress,PrefixLength

Then update antiX:

sudo fresh /etc/fstab
sudo fresh /usr/local/bin/mount-vmxfer

28. antiX duplicate IP cleanup and reboot check

Earlier, the antiX VM showed duplicate static and DHCP IPs. The correct permanent state is one IP per interface:

eth0: DHCP from VMnet8 NAT, default route allowed
eth1: DHCP from VMnet1 host-only, no default route

After reboot, check:

ip -4 addr
ip route

Correct pattern:

default route only via eth0 / 192.168.254.2
192.168.4.0/24 route via eth1
no duplicate 192.168.254.129/24 static address
no duplicate 192.168.4.128/24 static address
no default route via eth1

If duplicates return, diagnose before editing randomly:

ps -ef | grep -E 'connmand|dhclient|dhcpcd|NetworkManager|wicd|ifplugd' | grep -v grep

sudo grep -R "192.168.254.129\|192.168.4.128\|eth0\|eth1" \
  /etc/network /etc/connman /etc/ceni /etc/default /etc/runit /etc/rc.d 2>/dev/null

cat /etc/network/interfaces 2>/dev/null
ls -la /etc/network/interfaces.d 2>/dev/null

Temporary cleanup if duplicate addresses appear again:

sudo ip addr del 192.168.254.129/24 dev eth0 2>/dev/null
sudo ip addr del 192.168.4.128/24 dev eth1 2>/dev/null
sudo ip route del 0.0.0.0 dev eth1 2>/dev/null
sudo ip route del default dev eth1 2>/dev/null

Then re-check:

ip -4 addr
ip route
ip route get 1.1.1.1
ip route get 192.168.4.1
